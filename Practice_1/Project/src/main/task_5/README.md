**Тут пояснения про мотивировку и цену изменения.**

1) Identifiable - сделан интерфейсом, не является абстрактным классам, так как он ему попросту не нужен мы не хотим тут хранить поля или методы, которые будем передавать по наследству, а наследовать можно только от одного класса, что нам будет дорого просто так это делать. Так же интерфейс тут не даёт возможность создать объект new Identifiable, ведь это будет абсолютно бессмысленный объект, который будет только мешать.

Само по себе добавление методов в интерфейс заставит переписывать классы, который реализуют этот интерфейс.

2) BaseEntity - является абстрактным классом, опять же не  даёт возможность создать бессмысленный объект new BaseEntity, ведь это 
будет сущность без явного понятия зачем она нужна, просто будет один id и геттер для id, но нам нужно от него наследоваться, потому что в принципе нам нужно поле id как для курсов, так и для студентов ну и геттер для него, поэтому абстрактным класс.

Расплачиваемся тем, что BaseEntity касается всех наследников, соответственно, если что-то переделаем в BaseEntity это коснётся всех наследников, наследоваться можно только от одного класса и конструктор наследника обязан первой строкой вызвать конструктор родителя через super().

3) CoursePolicy - интерфейс с одним методом, опять же интерфейс хорошо подойдёт даёт каркас и дальше разные обычные классы реализуют метод под свои нужды, как тут сделано один проверяет возраст студента, другой а открыта ли запись на 
курс вообще. Удобство в том, что если нужно новое правило, то это отдельный класс с реализацией метода canEnroll.

Опять же появление нового метода придётся реализовывать этот метод везде, где интерфейс передаётся.

4) Formatter - Тут абсолютно аналогичная ситуация как и с CoursePolicy, добавить нечего.

5) ClockProvider - тут выбор пал на отсутствие конкретного типа. В джаве уже есть готовая стандартная библиотека с типами и методами, тогда смысл придумывать обычный класс, интерфейс, абстрактный класс или ещё чего.

Цена изменению тут переписывание метода в Main и сам метод main слегка.
